# Third-party MCP tool input schemas (test corpus)

These 60 files are input schema fixtures from 17 real MCP servers: 45 literal source snapshots and 15 mechanically derived schemas. The derived fixtures are identified below; some approximate the runtime schema rather than reproducing the SDK's exact output. They are third-party works used **only as test data** for Probe's tool classifier and schema normalizer/generator. Each remains the property of its authors and is subject to the license of its source repository (column *License*). Attribution: the MCP reference servers are © Anthropic, PBC and MCP contributors (modelcontextprotocol/servers, modelcontextprotocol/servers-archived); the other schemas are © their respective project authors (GitHub, Inc.; the containers/kubernetes-mcp-server authors; Flux159/mcp-server-kubernetes authors; Notion Labs).

Each file is the bare `inputSchema` object, pretty-printed (2-space indent), with no wrapper fields. Names are `<server>__<tool>.json`.

## Kinds

- **literal**: the schema exists as JSON Schema in the source (a tool-definition object, a Python dict, or a JSON tool snapshot) and is copied unchanged. For `k8s-flux159` three shared parameter constants imported from `src/models/common-parameters.ts` are inlined.
- **derived**: the source defines the schema in another form, so the file was produced mechanically from the unmodified definition:
  - `filesystem__*`, `everything__*`: the zod expressions copied verbatim from the source and rendered with zod 4 `z.toJSONSchema(schema, {io: "input"})`. This is an approximation of the SDK's own output (it includes `$schema`, and zod 4 may differ in small details from what the server actually publishes).
  - `fetch__fetch`, `git__*`: the pydantic model classes copied verbatim from the source and rendered with pydantic 2.14.4 `model_json_schema()`, which is how that server version builds its tool schemas.
  - `notion__*`: generated by running the project's own `OpenAPIToMCPConverter.convertToMCPTools()` (`src/openapi-mcp-server/openapi/parser.ts`) on the checked-in `scripts/notion-openapi.json`. Only the converter ran, not the server. Each tool carries the shared `$defs` block.
